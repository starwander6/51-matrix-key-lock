## 一：矩阵键盘->矩阵键盘密码锁  

矩阵键盘的原理图核心在于**用较少的 I/O 口控制较多的按键**。以最常见的 4×4 矩阵键盘为例，它将 16 个按键排列成 4 行 4 列的矩阵，每一行和每一列的交叉点放置一个按键。这样，单片机只需要 8 个 I/O 引脚（4 行 + 4 列）就能识别 16 个按键，比一对一连接节省了一半的引脚。

---

### 原理图连接方式

1.  **行列线交叉**：4 根行线（Row0~Row3）和 4 根列线（Col0~Col3）呈网格状交叉。每个按键的一端连接行线，另一端连接列线。
2.  **外部上拉电阻**：看原理图，左侧那个标着 RP7 和 RP11 的蓝色方块是**排阻（电阻网络）**。你可以看到它里面有 8 个独立的电阻，每个电阻的阻值写着 10K（10000Ω），矩阵键盘，行线（P1.4~P1.7）和列线（P1.0~P1.3）都连在了 P1 口，因为 P1 口外面硬生生接了一个 10K 的外部排阻 拉到 VCC。所以在写代码扫描键盘时，只要你没有按下按键，**读出来的永远是稳定的高电平（1）**。当某一行输出低电平（0），按键按下时，列线就会瞬间被拉低到 0V，单片机就能检测到。
3.  **I/O 口分配**：逐行扫描时：行线通常配置为输出，列线配置为输入（用于读取状态）；逐列扫描时：列线通常配置为输出，行线配置为输入（用于读取状态）；线反转法：行线与列线双向操作配合；

---

### 扫描原理
**数码管扫描**（输出扫描）：输送显示的数据
	原理：显示第1位→显示第2位→显示第3位→……，然后快速循环这个过程，最终实现所有数码管**同时**显示的效果。

**矩阵键盘扫描**（输入扫描）：单片机读取按键的状态
	原理：读取第1行(列)→读取第2行(列) →读取第3行(列) → ……，然后快速循环这个过程，最终实现所有按键同时检测的效果。

原理图本身只是静态连接，按键的识别依赖于**单片机对引脚电平的动态控制**，主要有三种方法：

**1.逐行扫描法**
简单来说，程序依次将每一根**行线拉低**（输出 0），其余行线保持高电平，**然后**立即读取所有**列线**的状态。
*   **无按键**：该行所有列线均为高电平（被外部上拉电阻拉高）。
*   **有按键**：如果该行有按键被按下，对应的列线就会被拉低。例如，若 Row0 拉低时，读到的 Col1 为低电平，说明 Row0 与 Col1 交叉处的按键被按下了。
*注：看自己51开发板原理图上P15口是否连接在五线四相步电机那里，若是，则会连接到BZ，BZ又会连接在蜂鸣器上，蜂鸣器会响，故逐行扫描会出现一些小问题*。  
*默认状态：所有行线、列线都设置为**输入**（或者输出高电平）。因为有内部/外部上拉（这个开发板是外部上拉），所有线都是高电平。*   

**具体步骤**：
* 扫描第一行：单片机把 Row0 配置为**输出低电平（0）**，其他行保持高电平。  
* 读取列线：此时，单片机把 Col0~Col3 配置为**输入并读取状态**。  
* 如果 S1 没按下，Col0 有上拉电阻，读到的还是高电平。   
* 如果 S1 按下了，Row0（此时是0V）就和 Col0 导通了，**Col0 的电平被强行拉低**，单片机就能读到低电平（0），从而知道 S1 被按下了。  
* 扫描下一行：将 Row0 恢复高电平，把 Row1 输出低电平，重复上述步骤，以此类推。    

**2.逐列扫描法**
与逐行扫描非常类似，先把第1列拉低（输出0），其余列拉高，然后读取4根列线的状态。如果此时有按键按下，对应的行线就会变低。如果没有，就换第2列拉低，再读行线……以此类推。

**3.线反转法/行列反转法（速度更快）**
这种方法分两步，适合 I/O 口可双向读写的场景：
* 第一步（读列）：把所有的行引脚设置为输出并拉低（0），所有的列引脚设置为输入并开启上拉（1）。然后读取列引脚的值。如果有按键按下，那么按键所在的那一列会被拉低（变成0）。这样我们就知道了按键在哪一列。
* 第二步（读行）：把刚才的状态反转过来。所有的列引脚设置为输出并拉低（0），所有的行引脚设置为输入并开启上拉（1）。然后再读取行引脚的值。如果有按键按下，按键所在的那一行会被拉低（变成0）。这样我们就知道了按键在哪一行。
* 第三步：组合：知道了**行号和列号**，就能唯一**确定按键的位置**。

---

### 硬件设计中的注意点

*   **按键消抖**：机械按键在闭合瞬间会产生 5~20ms 的抖动，原理图上通常会在按键两端并联一个小电容（如 0.1μF），或者在软件中配合**延时**/计数逻辑来消除抖动，**防止**一次按下被**误判**为多次。  
*   **防冲突（鬼键）**：在标准无二极管矩阵中，如果同时按下三个构成矩形的按键（当你同时按下三个（或更多）按键，且这三个按键刚好占据了矩阵中的**两个行和两个列**，形成了一个矩形或直角三角形的三个顶点），可能会产生“鬼键”导致误判。如果应用场景需要支持组合键或多键同时按下，通常需要在每个按键上串联一个二极管（利用单向导电性）来隔离。

## 二：LCD1602

---

LCD1602是一个**自带字库**的**微型显示器**。它的全称是 Liquid Crystal Display（液晶显示），16 代表每行能显示 16 个字符，02 代表能显示 2 行。

### 原理图介绍

---

**VO**：**对比度调节电压**，这个脚用来调节屏幕黑白深浅或字的浓淡，VO电压越低，对比度越高，字越黑  **电位器**作用：把电位器两端分别接 5V 和 GND，中间抽头接 VO。旋转电位器时，VO 上的电压就会在 0~5V 之间平滑变化，你就能找到一个字符最清晰、背景最干净的“甜点电压”，有实验数据表明，某些 1602 屏在 VO 电压调到 0.3V~0.4V 时对比度效果最好。

为什么存在背光灯电源正极和负极？（**BG VCC (BLA)**:背光灯电源正极    **BG GND(BLK)**:背光灯电源负极）
LCD1602 的液晶本身不发光，它靠**反射环境光**来显示。背光引脚（通常是 15 脚 A / 16 脚 K）内部连接的是**LED 背光灯**，用来照亮屏幕。
    
*背光灯电源正负极是独立于显示逻辑的一对引脚，专门为屏幕背面的 LED 灯供电，让屏幕在暗处也能看清。*  

---

**3个控制引脚**

* **RS（数据/命令选择线）**：非常重要。`RS = 0` 时，单片机发给 LCD 的是“**命令**”（比如：清屏、光标移动）；`RS = 1 `时，单片机发给 LCD 的是“**数据**”（比如：字母 'A' 的 ASCII 码）。  
* **RW（读/写选择线）**：**`RW = 0` 时，单片机向 LCD 写入**；RW = 1 时，单片机从 LCD 读出状态。（实际开发中，我们几乎只用写，不用读，所以经常直接**把 RW 接地（低电平）**，省一根引脚）。  
* **E（使能线）**：这是一个“盖章”信号。当数据或命令准备好放在数据线（D0-D7）上后，给 E 引脚一个高电平跳变到低电平（**下降沿**）的脉冲，LCD 就会把数据“吃”进去。（1为数据有效 下降沿执行命令）    
注：*(D0-D7 是 8 位数据线，负责传输具体的指令或字符代码)* 

--- 

### LCD1602时序图介绍
* **tSP1 (Setup Time for RS)**：在 E 引脚拉高（上升沿）之前，RS 和 R/W 信号必须已经保持稳定的时间。

* **tSP2 (Setup Time for Data)**：在 E 引脚拉高之前，数据线上的数据（DB0-DB7）必须已经准备好的时间。

* **tR (Rise Time)**：E 信号从低电平跳变到高电平所需的上升时间。

* **tpW (Pulse Width)**：E 信号保持高电平的宽度（脉冲宽度）。通常要求大于 150ns（或 450ns 视芯片而定），单片机发 E=1 后需要稍微延时一下才能发 E=0。

* **tf (Fall Time)**：E 信号从高电平降到低电平的时间。

* **tHD1 (Hold Time for RS/RW)**：E 引脚变为低电平（下降沿）之后，RS 和 R/W 信号必须继续保持稳定的时间。

* **tHD2 (Hold Time for Data)**：E 引脚变为低电平之后，数据线（DB0-DB7）上的数据必须继续保持稳定的时间。（因为芯片是在下降沿读取数据，读取需要一点时间）。

* **tc (Cycle Time)**：一个完整的写操作周期。即从这一次操作开始，到下一次操作开始的最小时间间隔。

* **tD**(图里没标，但在手册里常叫 Data Hold/Valid time)：隐含在 Valid Data 区域，表示数据在 E 下降沿前后必须稳定的总时间。

---

**所以一个标准的“写操作”函数必须长这样：**

* 1.配置 RS（你要写指令还是写数据，设置好高低电平）。

* 2.配置 R/W 为低电平（表示你要写）。

* 3.把 8 位数据放到 DB0-DB7 上。

* 4.稍微延时一下（满足 tSP1 和 tSP2，通常几十纳秒，单片机主频不高的话直接执行下一条指令就行）。

* 5.把 E 拉高（E = 1）。

* 6.延时一会儿（满足 tpW，通常单片机指令周期本身就够了，如果主频太高，需要延时个1ms。

* 7.把 E 拉低（E = 0）。 -> 【重点】芯片在这一刻读取了数据！

* 8.稍微延时一下（满足 tHD1 和 tHD2），然后才能去改变 RS 或数据线。

**结论**：E 的下降沿是触发写入的开关，而**开关按下前后**，**其他的信号（RS、数据）必须保持稳定，不能马上变**”。

---

### LCD1602 的核心特点

* **自带字库（只读存储器 CGROM）**：（Character Generator Read-Only Memory字符发生器只读存储器）它包含了 LCD1602 出厂就固化好的所有标准字符（如英文字母、数字、标点符号等）。你只要告诉它“显示字母 A”，它自己就会去字库里找 A 的字形亮出来。  
* **可以自定义字符（CGRAM）**：( Character Generator Random Access Memory字符发生器随机存取存储器)除了内置字库，它内部还有 8 个可以让你自己画字符的空间（比如你可以画个温度计图标、心形符号）。  
* **只能显示字符**：注意，它不能直接显示中文！（因为内置字库没有汉字，除非你自己用自定义功能画汉字，但极其麻烦）。  
* **并口通信**：它通过多根线同时传输数据，速度比 I2C 或 SPI 快，但占用单片机的引脚比较多。  
*CGROM 和 CGRAM 的核心区别在于：**CGROM 是只读的、出厂固化好的标准字库；CGRAM 是可读写的、留给用户自定义字符的小块内存**。前者决定了屏幕能显示哪些标准字符，后者让你能创造少量特殊符号。* 

| 特性 | CGROM (字符发生器只读存储器) | CGRAM (字符发生器随机存储器) |
| :--- | :--- | :--- |
| **存储性质** | 只读 (ROM)，出厂固化，用户无法修改 | 可读写 (RAM)，用户可通过程序随时改写 |
| **主要用途** | 存储标准字库（如英文字母、数字、日文假名等） | 存储用户自定义的特殊字符或图标 |
| **字符数量** | 容量较大，通常包含上百个标准字符（如 192 个或 240 个） | 容量很小，通常仅支持 **8 个** 5×8 点阵字符（或 4 个 5×10 点阵字符） |
| **调用方式** | 直接向 DDRAM 写入对应字符的 ASCII 码/字符码 | 需先向 CGRAM 写入自定义点阵数据，再向 DDRAM 写入对应的自定义字符码（通常为 0x00~0x07） |

### 核心逻辑：写入“命令” vs 写入“数据”

 * **写命令（Write Command）**：`RS=0;` 送命令码; 给E引脚脉冲;
   * 你用它来告诉 LCD：“我要清屏了”、“光标移到第一行第一个了”、“准备显示”。  
 * **写数据（Write Data）**：`RS=1;` 送数据; 给E引脚脉冲;
   * 你用它来告诉 LCD：“在这个位置显示字母 'H'”、“显示数字 '8'”。  

*结合数码管的“消影”：*    
*数码管需要不断扫描才能显示；但 LCD1602 不需要不断刷新！只要你不去改变它，就算单片机死机了，它依然会保持屏幕上的画面。所以它的程序里没有“消影”，也不需要放在定时器里频繁扫描。*

### 初始化流程 
* 1.**功能设置（命令 0x38）**：告诉它工作在 8 位数据接口、2 行显示、5x7 点阵模式。  
* 2.**显示开关控制（命令 0x0C）**：显示开，光标关，闪烁关  
* 3.**清屏（命令 0x01）**：把屏幕清空，光标回到左上角。  
* 4.**输入模式设置（命令 0x06）**：设置写完一个字符后，光标自动向右移一位。

### 显示字符
* 1.发送/写指令（0x80|AC）//设置光标位置(AC 指 Address Counter（地址计数器）)
* 2.发送数据   &emsp;&emsp;        //发送要显示的字符数据
##### AC的核心作用
* **指向当前访问位置**：读写 DDRAM（显示数据）或 CGRAM（自定义字符点阵）时，AC 保存的就是当前操作的地址。写一个字节后，AC 会自动加 1（或减 1），实现连续写入。

* **区分 DDRAM 与 CGRAM**：通过设置地址的最高位（DB7）来区分。**当 AC 值最高位为 1 时，表示指向 DDRAM**；**为 0 时指向 CGRAM**。具体由指令中的地址位决定。

* **与 CGRAM 的关系**：自定义字符时，先发"**设置 CGRAM 地址"指令**把 AC 指向 CGRAM 的某个位置，然后连续**写入 8 个字节的点阵数据**，AC 自动递增，写完一个字符的 5×8 点阵。之后再把 AC **切回 DDRAM**，**写入自定义字符码**（0x00~0x07）来显示。

###### 与 CGROM/CGRAM 的衔接
CGROM 是只读的，不需要 AC 去写；CGRAM 可写，写之前必须用 AC **定位**。所以 AC 是"你操作 CGRAM 时的写指针"，也是"你操作 DDRAM 显示内容时的位置指针"。简单说：**CGROM 靠字符码查表，CGRAM 靠 AC 定位写入，DDRAM 靠 AC 定位显示位置**。

## 三：模块化编程  

模块化编程是一种将程序拆分为**独立**、**可复用**模块的编程范式。把各个模块的代码放在不同的.c文件里，在.h文件里提供外部可调用函数的声明，其它.c文件想使用其中的代码时，只需要#include "XXX.h"文件即可。  
#### 在 C 语言中，.c 和 .h 文件是模块化编程的基本载体。理解它们的分工，就理解了 C 语言如何组织代码。

### 两种文件的角色
**.h 文件（头文件，header） 存放声明**：函数原型、宏定义、类型定义（struct、typedef、enum）、全局变量声明、以及被多个文件共享的接口。它描述"有什么"，不产生实际的代码实体。  

**.c 文件（源文件，source） 存放定义和实现**：函数体、全局变量的实际分配、内部使用的静态函数和静态变量。它描述"怎么做"。  

## 四.准双向口/输入&输出


### 核心概念：什么是“准双向口”？

---

*   **真正的双向口**：内部有复杂的逻辑判断，你不需要管它是输入还是输出，直接连上就能用。
*   **51 的准双向口**：
    *   当你要输出低电平时，单片机**内部开关打开**，**强力把引脚“拉”到地（0V）**。
    *   当你要输出高电平时，单片机内部开关关闭，引脚仅仅依靠内部一个很弱的“上拉电阻”（电阻阻值是很大的，最后流出来的电流只有几十/几百微安级别）连接到 VCC（5V）。这个上拉电阻很**弱**（相当于**能提供的电流很小**）。
    *   **致命弱点**：如果你把这个引脚强行接地（0V），由于内部上拉电阻很弱，它很容易被“拉低”。

---

### 输出（Output）

**向引脚写 `0` 或 `1`。**

*   **输出低电平（0）**：
    *   **代码**：`P1 = 0x00;` (或者 `P1_0 = 0;`)
    *   **内部动作**：单片机内部的开关导通，引脚直接接地。
    *   **能力**：**很强**。它可以吸收（灌电流）很大的电流，通常 51 单片机一个引脚可以吸收 10mA~20mA 的电流。所以，**驱动 LED 灯时，通常采用“低电平点亮”（共阳极接法）**，因为单片机“拉低”的能力比“推高”的能力强得多。
*   **输出高电平（1）**：
    *   **代码**：`P1 = 0xFF;` (或者 `P1_0 = 1;`)
    *   **内部动作**：单片机内部的开关断开，引脚通过内部上拉电阻连接到 VCC。
    *   **能力**：**很弱**。它只能提供极其微弱的电流（几十/几百微安）。如果你想用它直接驱动一个 LED 灯（高电平点亮），灯会非常暗甚至不亮。**它只能用来作为信号传输，不能用来驱动负载。**

---

### 输入（Input）

**读取引脚上的电平状态。**（比如读按键是否按下）

由于 51 是准双向口，**在进行输入操作前，必须先向该引脚写 `1`**。

*   **为什么必须先写 `1`？**
    *   假设你之前让这个引脚输出了低电平（0），此时内部开关是导通的，引脚被牢牢接地（0V）。
    *   现在你想把它当输入用，外部的信号想给它一个高电平（比如按键没按下时，外部上拉电阻给的高电平）。但是，因为内部开关还导通着，外部的高电平会被强行拉低，你读到的永远是 `0`。
    *   所以，写 `1` 的作用是：**关闭内部的下拉开关，释放引脚的控制权，让引脚依靠内部上拉电阻维持高电平，从而让外部设备能够自由地控制这个引脚的高低电平。**

*   **正确的输入流程**：
    ```c
    P3 = 0xFF;      // 1. 先写 1，把引脚设为高电平（释放引脚）
    if (P3_1 == 0)  // 2. 再去读取引脚的状态
    {
        // 发现按键按下了
    }
    ```

---

### 特例：P0 口

P0 口比较特殊，它的内部**没有上拉电阻**（或者说只有极弱的上拉场效应管）。它是一个**真正的双向口（漏极开路）**。

*   **作为输出**：如果你直接写 `P0 = 0xFF;`，P0 口实际上是**悬空**的，没有任何电平输出。除非你在外部接上拉电阻（通常接 10k 排阻到 VCC），否则它输出不了高电平。
*   **作为输入**：同样需要先写 `1`，但必须依赖外部电路提供高电平。

---

### 读引脚”&“读锁存器”

51 的 I/O 口有两种读取方式：

1.  **读引脚（Read Pin）**：真实读取外部物理引脚的电压状态。比如 `if (P3_1 == 0)`，这就是读引脚，常用于读取按键。
2.  **读锁存器（Read Latch）**：读取单片机内部保存你上次写进去的那个数据，不管外部引脚被拉成什么样。

**为什么要区分？**
因为有些指令叫**“读-改-写”指令**。比如 `P1 = P1 | 0x01;`。
它的执行过程是：先读取 P1（读的是锁存器里的值，而不是物理引脚，防止外部电路干扰），在内部做“或”运算，然后再写回 P1。
如果你用这种指令去操作按键（比如把按键所在的引脚当输入用），就会出现逻辑错误。所以，**按键输入通常用位操作（`P3_1`），而驱动外设（如控制流水灯）常用整体赋值或逻辑运算。**

### 总结口诀：
*   **输出 0**：使劲往下拉（能力强，能点灯）。
*   **输出 1**：软弱无力挂上去（靠弱上拉，只能当信号）。
*   **要输入**：必须先写 1，关闭内部下拉，**防止外部信号被拉死**。
*   **P0 口**：记得外接上拉电阻。
